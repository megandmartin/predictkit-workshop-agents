Set up once

No API key, wallet, RPC, or PredictKit server is needed for this kit. Your coding assistant needs its own normal sign-in.

1. Clone the workshop repo

Run this in a terminal. Keep the cloned folder as your assistant’s workspace so its skills and roles can be found.

git clone https://github.com/megandmartin/predictkit-workshop-agents.git cd predictkit-workshop-agents

2. Open the folder

Codex: open the cloned folder as a project. Claude Code: run claude from that folder. Then use the setup prompt below; the assistant creates the ignored workshop brief for you.

# Claude Code terminal route claude # Codex terminal route, if you use its CLI codex

Prefer the desktop app? Opening the same cloned folder there is fine. Without Git, use GitHub’s Download ZIP and open the extracted root folder. If you need the assistant itself, follow the official Codex quickstart or Claude Code setup. Do not work from a different project folder unless you copy the kit’s instructions and skill directories too.

Copy the prompts, in order

Pick your assistant. Each button copies the entire prompt. Keep the workspace open in this repository and use the same runs/workshop/ folder for every step.

Read AGENTS.md and WORKSHOP.md. Create runs/workshop/brief.md by copying examples/brief.md. Show me the user decision, market question, resolution rule, and VOID policy I need to edit. Ask me for my workshop idea, then stop. Do not start discovery or build anything yet.

Read AGENTS.md, WORKSHOP.md, and runs/workshop/brief.md. Treat that brief as frozen. Read every skill assigned to each role in the README map from .agents/skills/. Stop for my review of the memo. Do not create app or submission files yet.

Only after you approve the memo
I have reviewed runs/workshop/decisions/build-memo.md and approve its specific scoped off-chain simulation. If that memo recommends revising the brief or lacks an implementable contract, stop and ask me to resolve it before building. Read the frozen brief, approved memo, discovery files, and agents/frontend.md, agents/domain.md, and agents/submission.md. Verify the result

Before you show the demo
Read agents/reviewer.md, .agents/skills/verify-outcome/SKILL.md, and .agents/skills/collect-evidence/SKILL.md. Review every file under runs/workshop/ against the frozen brief and approved memo. Open the local HTML in a browser if a browser tool is available; test probability input, invalid values, close, YES, NO, VOID, repeat resolution, reload, and keyboard use. Validate market.json. Write runs/workshop/qa/review.md with what you actually executed versus only inspected. Call this independent only if a separate fresh context performs the review.

The example brief is for practice. For a real idea, replace its illustrative user and market terms before sending “Discover and decide.” If Codex cannot delegate to separate contexts, the sequential prompts still work. If Claude Code reports that your usage limit is exhausted, wait for your account’s reset; the skill files themselves need no provider key.

What does “works” mean here?

A convincing workshop demo is a useful step, but its evidence must stay precise. These checks tell you what you can actually claim.

  • FILEThe brief, memo, prototype, contract, story, and review exist in runs/workshop/.
  • TESTThe HTML opens locally; forecast, close, resolution, VOID, and reload behave as recorded.
  • GATEThe market contract retains the exact question and rules; you approved the memo before building.
  • CLAIMSay “off-chain simulation” until live AI, Solana read-back, deployment, and real participant completion have their own proof.
