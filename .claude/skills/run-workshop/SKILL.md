# Run the workshop

Use for the facilitator, not for every role. Read `WORKSHOP.md` and `docs/index.html` first. This kit supplies Markdown instructions and a visual guide; it does not contain the original Python coordinator or automatically run eight agents.

## Before participants arrive
Clone the public repository into the participant's workspace and confirm Codex or Claude Code can read the project role and skill folders. Copy the sample brief to ignored `runs/<slug>/brief.md`; replace illustrative assumptions for a real idea. Keep credentials, wallet material, and personal notes out of Git. Test one prompt and the local HTML opening path before the room begins.

## Facilitate the bounded phases
1. Freeze the user decision, exact question, resolution rule, and VOID policy.
2. Run research, product, and architecture from the same brief. Sequential execution is valid.
3. Have the chief reconcile them into a memo. Stop for human review; a generated memo cannot approve itself.
4. After approval, build the HTML, JSON/resolution guidance, and pitch/demo/application drafts from the approved inputs.
5. Review all files and run browser checks where tools exist. Label a same-context pass second self-review.
6. Rehearse one demo and identify the next proof required for the claim the participant wants to make.

## Completion and limits
A useful local prototype and continuation plan are sufficient workshop outcomes; finished startup, live AI quality, deployed Solana flow, and three independent participant completions require separate evidence. Never use real-money trading or first-time wallet setup in the critical path. This skill grants no tool access or publishing authority.
